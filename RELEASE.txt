HOW TO RELEASE DEALERDESK
=========================

Releases are built by GitHub Actions from a version tag. Nothing is built
or tested by hand any more.

1. Make sure the change is on master and the CI run for it is green
   (GitHub -> Actions -> CI). CI builds the program and runs all the tests
   on every push.
2. Tag the commit and push the tag:

       git tag -a v2.4 -m "DealerDesk 2.4"
       git push origin v2.4

3. The "Release" workflow waits for approval (GitHub -> Actions -> the run
   -> Review deployments -> production), then builds the Linux binary, runs
   every test again, and publishes a GitHub Release named after the tag with
   the binary and a SHA256SUMS file attached (GitHub -> Releases). If a test
   fails, no release is published. The approvers are the required reviewers
   of the "production" environment in the repository settings.
4. Download the binary from the release page. On \\fileserver01\apps\dealerdesk\
   rename dealerdesk to dealerdesk.old, then copy the new binary there as
   dealerdesk.
5. Email the showrooms that a new version is out.
6. If something breaks, copy dealerdesk.old back. Every earlier release can
   also be downloaded again from the Releases page.

Notes

- The tag is the release number. The version shown on screen comes from
  screen.c and is changed by hand in the same commit when it moves on.
- The workflow produces the Linux binary only. Windows builds are not
  covered by it.
